# Phase 2 Implementation Plan

> Spec: `docs/superpowers/specs/2026-10-22-phase2-design.md`. Same global constraints as Phase 1 (integer money, orgId on every query, `withAuth` on every action, transactions for stock, no console errors).

### Task A: Serial numbers
- Models: `SerialNumber`; `Product.trackSerial`, `Product.warrantyMonths`; `Sale.lines[].serials` already exists in the plan schema → add field.
- Services: `serials.ts` (`assertSerialsAvailable`, `markSold`, `restore`, `receiveSerials`, `findBySerial`, `history`); wire into `completeSale`, `returnSale`, `voidSale`, `receivePurchase`, `returnPurchase`, `transferStock`, `adjustStock`; `findByCode` falls back to serial lookup.
- UI: product form switch + warranty; receive dialog serial entry (scan); POS serial capture dialog; adjust/transfer serial pickers; `/inventory/serials` lookup; serials on receipt/invoice.
- Tests: integration (double-sell race, return restores, purchase requires count), role matrix entries, e2e lifecycle.

### Task B: Offline POS
- `public/sw.js`, `src/components/offline/register-sw.tsx`, `src/lib/idb.ts` (tiny promise wrapper), `src/components/offline/offline-store.ts` (snapshot/outbox/meta), `src/lib/offline-number.ts` (pure, tested).
- Server: `Device` model, `actions/offline.ts` (`registerDevice`, `posSnapshot`, `syncOfflineSales`), `services/offline-sync.ts`.
- POS: online/offline mode switch, local lookups, local checkout + local receipt (`lib/receipt-html.ts`), sync banner, Sales “Needs review” filter.
- Tests: unit (numbering, receipt html escaping), integration (idempotent sync, conflicts), e2e (context.setOffline → sell → reload → online → synced).

### Task C: E-invoice & e-way bill
- `lib/gstin.ts` (checksum), `lib/einvoice.ts` (builder + validator + UQC), `server/crypto.ts` (AES-GCM secrets), `server/services/nic.ts` (client), `server/services/einvoice.ts` (generate/cancel/ewb/json), `actions/einvoice.ts`, settings page `/settings/einvoice`, sale page panel, invoice print additions.
- Tests: unit (builder, validator, checksum, crypto), integration with mock NIC HTTP server, role matrix, e2e via mock NIC (env `NIC_MOCK_URL` only in tests).
